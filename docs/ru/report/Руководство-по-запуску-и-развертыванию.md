# Руководство по эксплуатации и развертыванию

## Область применения
- Первое использование на рабочем столе
- Service Версия работает независимо
- Docker Развертывание
- macOS Первый выпуск

## Быстрый старт
1. Запустите рабочий стол и нажмите «Запустить службу».
2. Войдите в «Управление учетной записью», добавьте учетную запись и завершите авторизацию.
3. Если обратный вызов завершился неудачно, вставьте ссылку обратного вызова, чтобы завершить анализ вручную.
4. Обновите использование и подтвердите статус учетной записи.

## Подключение через ccswitch
Для подключения к CodexManager через ccswitch или Codex CLI сохраните вход ChatGPT в Codex и укажите platform key только в `config.toml`.

1. Выполните `codex login` в целевом профиле Codex и войдите с любым аккаунтом ChatGPT. При собственном `CODEX_HOME` вход Codex и CodexManager должны использовать один каталог.
2. Убедитесь, что в созданном `auth.json` задано `auth_mode = "chatgpt"`, а `tokens.id_token`, `tokens.access_token` и `tokens.refresh_token` — непустые строки. Токены должен создавать Codex.
3. Откройте `Platform Keys` и создайте универсальный key.
4. Примените подключение через CodexManager на странице подключения Codex или обновите только `config.toml` через ccswitch по примеру ниже. Укажите platform key в `experimental_bearer_token` и убедитесь, что ccswitch не заменяет `auth.json` режимом API key.
5. Перезапустите Codex CLI после применения конфигурации.

Типичные пути:

- macOS / Linux: `~/.codex/auth.json`, `~/.codex/config.toml`
- Windows: `%USERPROFILE%\.codex\auth.json`, `%USERPROFILE%\.codex\config.toml`

Структура `auth.json` после входа (создаётся Codex; сохраните настоящий файл):

```json
{
  "auth_mode": "chatgpt",
  "tokens": {
    "id_token": "non_empty_value_generated_by_codex_login",
    "access_token": "non_empty_value_generated_by_codex_login",
    "refresh_token": "non_empty_value_generated_by_codex_login"
  }
}
```

- Настройка шлюза сохраняет `auth.json` байт в байт, а platform key записывает только в `config.toml`. Запуск CodexManager также не записывает `auth.json`.
- Если вход ChatGPT отсутствует, режим входа другой или обязательный токен пуст/отсутствует, настройка шлюза завершается ошибкой и сохраняет `auth.json` и `config.toml`. Файл авторизации не создаётся.
- Provider шлюза всегда использует `name = "cm"` и `requires_openai_auth = true`; переключатель удаления этого поля отсутствует.

Пример `config.toml`:

```toml
model = "gpt-6-sol"
model_provider = "cm"
review_model = "gpt-6-sol"
approval_policy = "on-request"
sandbox_mode = "workspace-write"
cli_auth_credentials_store = "file"
service_tier = "fast"

[model_providers.cm]
name = "cm"
base_url = "http://localhost:48760/v1"
wire_api = "responses"
requires_openai_auth = true
experimental_bearer_token = "replace_with_codexmanager_platform_key"
supports_websockets = true
```

- Если порт service изменён в Settings, обновите `base_url`.
- В режиме Docker / Web используйте доступный браузеру адрес Web с `/v1`, например `http://10.10.121.253:48761/v1`, вместо внутреннего адреса контейнера.

## Импорт и экспорт аккаунтов
- `批量导入`: выберите несколько файлов `.json/.txt` и импортируйте их вместе.
- `按文件夹导入`: доступно только на рабочем столе; после выбора каталога рекурсивно сканируйте файлы `.json` и импортируйте их пакетами. Пустые файлы будут автоматически пропущены.
- `导出用户`: после выбора каталога нажмите «Один файл JSON для каждой учетной записи» для экспорта, чтобы облегчить резервное копирование и миграцию.

## Service Версия
1. Загрузите `CodexManager-service-<platform>.zip` в Release и разархивируйте его.
2. Рекомендуется начать с `codexmanager-start`. Процесс запускает сервис + веб и может быть закрыт прямо в консоли `Ctrl+C`.
3. Вы также можете просто запустить `codexmanager-web`, который автоматически откроет `codexmanager-service` в том же каталоге и откроет браузер.
4. Или начните сначала `codexmanager-service`, а затем `codexmanager-web`.
5. Адрес по умолчанию: сервис `localhost:48760`, Web UI `http://localhost:48761/`.
6. Закрытие: посетите `http://localhost:48761/__quit`; если веб-сервис был запущен автоматически, он попытается закрыть его вместе.
7. Если вам необходимо выполнить обратный прокси-сервер самостоятельно или разделить статические ресурсы внешнего интерфейса, вы должны перенаправить `/api/runtime` и `/api/rpc` одновременно; только размещение статических файлов приведет к неправильной работе страницы управления.

## Docker Развертывание

### GitHub Пакеты / GHCR
- После выпуска Release образы `codexmanager-service` и `codexmanager-web` будут одновременно перенесены в пакеты GitHub (GHCR).
- Стабильные выпуски обновляют теги версии, `stable` и `latest`. Предварительные выпуски публикуют только тег версии и не заменяют плавающие теги.
- Для автоматического обновления используйте `stable`; для фиксации версии используйте, например, `docker pull ghcr.io/qxcnm/codexmanager-service:v0.6.0`.
- [`docker/docker-compose.release.yml`](../../../docker/docker-compose.release.yml) по умолчанию использует `stable`. Задавайте `CODEXMANAGER_RELEASE_TAG` только для фиксации версии.
- Пример: `CODEXMANAGER_RELEASE_TAG=v0.6.0 docker compose -f docker/docker-compose.release.yml up -d`
- `registry.cn-hangzhou.aliyuncs.com/kilimiao/codex-manager` не входит в текущий официальный процесс выпуска и может отставать. Поддерживаемые готовые образы находятся в GHCR по адресам `service` и `web`, указанным выше.

### Необязательное OTA-обновление Docker

- В официальном Release Compose есть отключённый по умолчанию sidecar Watchtower для проверки OTA. Оставьте `CODEXMANAGER_RELEASE_TAG` на плавающем теге `stable` и выполните:

  ```bash
  docker compose -f docker/docker-compose.release.yml --profile ota up -d
  ```

- Watchtower каждые 300 секунд проверяет отмеченные образы CodexManager service/web, но profile `ota` только сообщает о доступном обновлении и не заменяет контейнеры. Интервал можно изменить через `CODEXMANAGER_OTA_INTERVAL=60`.
- После согласия пользователя выполните однократную команду, чтобы загрузить новые образы и выполнить последовательный перезапуск:

  ```bash
  docker compose -f docker/docker-compose.release.yml --profile ota run --rm --no-deps codexmanager-ota --label-enable --run-once --cleanup --rolling-restart --stop-timeout 20s
  ```

- Если пользователь явно согласен на автоматическую проверку и обновление, включите profile `ota-auto`:

  ```bash
  docker compose -f docker/docker-compose.release.yml --profile ota-auto up -d
  ```

- Фиксированный тег, например `CODEXMANAGER_RELEASE_TAG=v0.6.2`, не переходит на следующие версии. Sidecar OTA получает доступ к Docker socket, поэтому включайте его только на доверенном хосте.
- После перезапуска service использует тот же том `/data` и выполняет автоматическую миграцию. Не удаляйте этот том во время обновления.

### Способ 1: создание докера
``` баш
docker compose -f docker/docker-compose.yml up --build
```

Браузер открывается: `http://localhost:48761/`

### Способ 2: сборка и запуск отдельно
``` баш
#сервис
docker build -f docker/Dockerfile.service -t codexmanager-service .
docker network create codexmanager-net

docker run --rm --name codexmanager-service \
  --network codexmanager-net \
  --network-alias codexmanager-service \
  -p 48760:48760 \
  -v codexmanager-data:/data \
  -e CODEXMANAGER_RPC_TOKEN=заменить_на_ваш_токен \
  codexmanager-сервис

# веб (между контейнерами используйте адрес Docker-сети, а не порт хоста)
docker build -f docker/Dockerfile.web -t codexmanager-web .
docker run --rm --name codexmanager-web \
  --network codexmanager-net \
  -p 48761:48761 \
  -v codexmanager-data:/data \
  -e CODEXMANAGER_WEB_NO_SPAWN_SERVICE=1 \
  -e CODEXMANAGER_SERVICE_ADDR=codexmanager-service:48760 \
  -e CODEXMANAGER_RPC_TOKEN=заменить_на_ваш_токен \
  codexmanager-web
```

- Примечание. Если вы хотите, чтобы пароль Web, элементы настройки, список моделей кэша и другой статус соответствовали службе, `codexmanager-web` и `codexmanager-service` должны использовать один и тот же том `/data`.
- Если контейнеру всё же нужно ходить в порт хоста, на Linux добавьте `--add-host=host.docker.internal:host-gateway`; без этого `host.docker.internal` часто не резолвится.

## macOS Первый запуск
- Текущая версия продукта macOS не была нотариально заверена с использованием учетной записи разработчика Apple, поэтому после первой загрузки из браузера Gatekeeper может выдать сообщение «Поврежден» или отказаться открывать.
- macOS `dmg` в версии Release имеют встроенные `Open CodexManager.command` и `README-macOS-first-launch.txt`.
- Рекомендуется сначала перетащить `CodexManager.app` в «Приложения», а затем дважды щелкнуть сценарий, чтобы завершить первый выпуск.
- Вы также можете выполнить его напрямую:

``` баш
xattr -dr com.apple.quarantine /Applications/CodexManager.app
```

- Если он по-прежнему заблокирован, снова выполните «щелчок правой кнопкой мыши -> открыть» на `CodexManager.app`.
